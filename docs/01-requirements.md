# 需求与验收标准

> 维护者：Doc Agent ｜ 最近更新：2026-11-18 ｜ 状态：已确认（G1 2026-11-18）
> 来源：`CR-001`（用户 2026-11-18 选择选项 A）

### R-001 网页端抽题应无可感知规律，且避免连续重复（优先级 P1，版本 v1）

- 来源：`CR-001`（`00-requirements-intake.md`）；用户原话：“不是真的随机 我点击了很多次还是一个题目，不够随机”“尽可能是随机 不能让我感受到的规律”
- 背景：服务端提交版按 `next_review ASC, created_at DESC` 确定性排序（`server/src/notes.js:363`），网页每次重新抽题都重置到 `queue[0]`（`web/src/views/QuizView.vue:96,111-118`），导致未评分时首题恒定。线上部署 `https://losnote.los-theseus.site/` 记录版本为 `3dfb6e2`，同样使用确定性排序。
- 描述：网页复习页点击「开始 / 重新抽题」时，应返回随机顺序的到期题；当到期题多于 1 道时，连续两次点击不得显示同一道题。纯随机仍可能在小样本下连续重复，因此允许在客户端加入“避重”兜底。
- 成功指标：与 `CR-001` 对齐。基线：6 道到期题连续 5 次首题恒为 `n6`（2026-11-18 内存库复现）。目标：见 `AC-001-1` / `AC-001-2`。
- 验收标准：
  - `AC-001-1`（正常路径）到期题 ≥ 5 时，连续点击「开始 / 重新抽题」20 次，首题至少出现 **3 道不同**题目。
  - `AC-001-2`（避重）到期题 > 1 时，任意连续两次点击「开始 / 重新抽题」，首题不得相同。
  - `AC-001-3`（边界：单题）到期题 = 1 时，允许每次显示同一题；页面不报错，不出现空白或无响应。
  - `AC-001-4`（边界：无题）到期题 = 0 时，显示「这一轮没有到期的题 —— 去题库加几条，或者等复习时间到。」；不发起无效重试，不报错。
  - `AC-001-5`（边界：栏目筛选）选择某栏目后，抽题只从该栏目的到期题中产生；切换栏目并重新抽题后，队列与当前题随之更新。
  - `AC-001-6`（错误路径）接口返回 401 或网络失败时，页面显示可读错误信息，不崩溃；恢复后再次点击「开始 / 重新抽题」可正常取题。
  - `AC-001-7`（兼容）`GET /api/quiz/due` 的响应字段与结构保持不变（`items`、`dueTotal` 及题目字段），旧网页端无需同步升级即可工作。
  - `AC-001-8`（性能）到期题 1000 道时，`GET /api/quiz/due?limit=1000` 在测试环境响应时间 < 100ms（同一机器、冷/热缓存各测 3 次取中位数）。
- NFR 影响：
  - 性能：适用。随机排序需对到期结果集排序；目标见 `AC-001-8`。若不达标，开发阶段需评估改用“随机抽样”实现（由 Dev 决定，Doc 不预设）。
  - 安全：不适用。不改鉴权、不新增输入面；令牌仍由现有 Bearer 中间件校验。
  - 隐私与数据保留：不适用。不新增采集、不改变保留期。
  - 兼容性：适用。API 响应结构不变；网页端与旧版服务端/旧版网页端的组合不应崩溃。
  - 可观测性：不适用。无新增后台任务、指标或告警要求。
  - 成本：不适用。不增加外部调用与持久化数据。
- 影响面：
  - 模块：服务端 `server/src/notes.js`（`listDue`）；网页端 `web/src/views/QuizView.vue`。
  - 接口：`GET /api/quiz/due`（仅顺序变化，契约不变）。
  - 数据：无表结构/字段变更，无迁移。
  - 配置：无新增环境变量。
  - 现有测试：`server/test/rest.test.js` 的到期查询断言、`web/e2e/crud.mjs` 的复习流程；需补随机性/避重用例。
- 不在范围内：
  - SRS 算法与三档评分规则；
  - 安卓端 `QuizFragment` 的抽题逻辑；
  - 题库内容、栏目管理、同步协议；
  - 线上部署操作本身（发布/重启由用户执行，见 `T-004`）。
- 变更历史：v1 2026-11-18 初始，来源 `CR-001`。
