## 4. 缺陷清单

### [P2] 杀死 `flock` 监督进程后 worker 无锁继续运行，第二个实例可并发

- 位置：`update.sh:101-133`（关键 `:128`：`flock -n -E 75 -o "$LOCK_FILE" env LOSNOTE_UPDATE_LOCKED=1 bash "$SELF" ...`）
- 问题：锁由 flock 监督进程持有；`-o` 在启动 worker 前关闭锁 fd，worker 不继承。若监督进程被 SIGKILL（非外层包装 shell 或 worker），内核立即释放锁，但 worker 继续 L1–L5；外层包装 shell 以 137 退出，看似更新已停止，实际 worker 仍在跑，第二个实例可立刻取锁并发。
- 触发：对 `flock ...` 进程单独 SIGKILL（运维只杀锁持有者、OOM/cgroup/外部 supervisor）。
- 影响：两个 worker 可同时执行 L2 备份与 L3 `up --build --force-recreate`；备份 JS 删除所有 `*.db.tmp` 可能删掉对方临时文件；两次重建可能冲突/重复停机；AC-002-7 在该边界被破坏。数据卷不会被删除。
- 证据：上述 distinct workers=2；杀死外层包装 shell 的对照组安全。
- 建议：去掉 `-o` 让 worker 继承锁 fd（脚本不后台启动长命子进程）；或 worker 自己在 0700 路径取锁并持有；或 worker 检测父进程/flock 存活并在失锁时退出。补“kill 监督进程 + 第二实例”回归。
- 置信度：高（机制与复现）；触发依赖外部 SIGKILL，非普通并发路径。

### [P3] `LOSNOTE_UPDATE_LOCKED=1` 可被外部设置，绕过整个锁

- 位置：`update.sh:104`、`:128`
- 问题：只检查环境变量；外部调用者可设置该变量跳过 wrapper；worker 子进程也继承该变量，重入同样绕过。
- 影响：另一实例持锁时可启动无锁 worker；锁不是安全边界，但属意外并发风险。
- 建议：worker 完成锁检查后 `unset LOSNOTE_UPDATE_LOCKED`；用随机 nonce/父进程校验替代可伪造标记；文档标注内部变量。
- 置信度：高。

### [P3] worker 退出码 75 会被 wrapper 误判为“锁冲突”

- 位置：`update.sh:126-131`
- 问题：`flock -E 75` 用 75 表示锁冲突；wrapper 仅凭 `rc == 75` 判定。若 worker 内未受保护命令返回 75，`on_error` 以 75 退出，wrapper 误报锁冲突。
- 影响：真实失败被误报为并发冲突，附带“无需回滚”；退出码仍 1，不改变结果。
- 建议：独立 marker/先试锁再 blocking 运行，不要只依赖 75；或用不与 worker 命令冲突的显式协议。
- 置信度：高（机制）；真实命令返回 75 概率低。

### [P3] `flock` 成为硬依赖，但帮助/文档未声明；BusyBox/旧 util-linux 的 `-E`/`-o` 未校验

- 位置：`update.sh:117`、`:128`、`--help`
- 问题：要求 util-linux flock 且支持 `-E`/`-o`；缺失时 fail_precheck 明确，但帮助/README/deploy 未列出前提；BusyBox flock 不支持时错误不阶段化。
- 建议：`--help`/`deploy.md` 声明前提；L1 检查 `flock --version` 或试运行；T-008 确认。
- 置信度：高。

### [P3] `/run/lock` 世界可写时，锁文件属主/权限未校验

- 位置：`update.sh:106-124`
- 问题：锁文件优先 `/run/lock`（本机 1777）；只拒绝符号链接，未校验既有普通文件属主/权限；本地用户可预创建普通文件造成锁绕过/DoS。
- 建议：校验属主/权限；`/run/lock` 世界可写时优先 `$HOME/.cache/losnote-update`（0700）或 mktemp 私有目录。
- 置信度：高（机制）；低（目标环境暴露面）。

### [P3] Bash < 4.4 下空 `ORIGINAL_ARGS[@]` 配合 `set -u` 可能报未绑定变量

- 位置：`update.sh:22`、`:128`
- 建议：`${ORIGINAL_ARGS[@]+"${ORIGINAL_ARGS[@]}"}` 或哨兵参数。
- 置信度：高（旧 bash 语义）；目标 Ubuntu 22.04 为 5.1，概率低。

- 建议：Doc 在 G3 后统一更新；`update.sh --help` 补 flock 前提。
- 置信度：高。

### [P3] `[::]` 候选地址逐地址等待 30 秒，IPv6-only 场景健康检查可能慢
