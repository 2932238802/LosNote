## 7. 缺陷清单（按严重度降序）

### [P2] 并发 `start()` 无序列保护，乱序响应会覆盖队列与避重基线

- 位置：`web/src/views/QuizView.vue:4`、`:8`、`:120-137`
- 问题：`start()` 没有请求序号、`AbortController` 或响应归属校验，任何一次成功响应都会无条件写 `queue.value` 与 `previousFirstUuid`；栏目下拉在加载中未禁用（只有按钮 `:disabled="loading"`）。
- 触发条件：复习页一次到期题请求在途（网络较慢）时，用户再次改变栏目下拉（`@change="start"`）；若第一次响应晚于第二次返回，旧响应会覆盖新队列，此时下拉显示新栏目但题目来自旧栏目。
- 影响：`AC-001-5` 的“切换栏目后队列随之更新”在此时序下被破坏；`previousFirstUuid` 来自过期响应，使下一次避重基线不准确。不会崩溃或丢数据。
- 证据：`QuizView.vue:4` 的 `<select ... @change="start">` 无 `:disabled`；`:120-137` 内无请求标识/取消逻辑；两次请求都写 `:127-128` 的共享状态。
- 建议：增加请求序号守卫（`const seq = ++reqSeq; ... if (seq !== reqSeq) return;`）或 `AbortController`；加载中禁用栏目下拉。该缺陷在改动前的 `start()` 结构上已存在，T-002 新增的非响应式 `previousFirstUuid` 使其影响扩大。
- 置信度：中（竞态窗口在慢网/快速切换时出现，静态逻辑确定）

### [P2] `loadCategories()` 与 `start()` 共写 `error`，401 友好文案可能被原始消息覆盖

- 位置：`web/src/views/QuizView.vue:111-118`、`:133`、`:175-179`、`:21-24`
- 问题：`loadCategories()` 的 `catch` 写入原始 `e.message`，`start()` 的 `catch` 写入 `quizErrorText(e)`，两者共用同一个 `error` ref 且并发执行，最终显示取决于哪个响应最后落地。
- 触发条件：进入复习页时令牌失效或网络断开，`/api/categories` 与 `/api/quiz/due` 都失败；若 categories 的 catch 后于 due 的 catch 执行，则 `error` 被覆盖为服务端原始文案（401 时为“令牌无效或缺失”），丢失“请到「设置」重新登录”的指引。另一个变体：categories 失败而 due 成功返回 0 题时，空状态从“没有到期的题”变成“取题失败”。
- 影响：AC-001-6 的最低要求（可读错误信息）仍满足，因为服务端 401 文案本身可读；但提示不确定、帮助性下降，且 AC-001-4 的正常空状态在罕见组合下被误标。不崩溃。
- 证据：`QuizView.vue:116` 为 `error.value = e.message`，`:133` 为 `error.value = quizErrorText(e)`；`:176-177` 同时调用 `loadCategories()` 与 `start()`；`:21` 的 `!queue.length && error` 直接使用同一 `error`。
- 建议：拆分为 `categoriesError` 与取题 `error`，或让 `loadCategories` 也走 `quizErrorText`，并只允许用户发起的取题请求驱动页面级错误。
- 置信度：高（代码路径确定；实际竞态触发率中）

### [P3] 单测只覆盖纯函数，未覆盖组件接线与模板状态链

- 位置：`web/test/quiz-order.test.js:1-107`、`web/test/quiz-error.test.js:1-32`、`QuizView.vue:19-29,120-137`
- 问题：测试只 import `../src/quiz-*.js`，没有验证 `QuizView` 是否实际调用 `orderForStart`、是否只在成功时更新 `previousFirstUuid`、`v-if/v-else-if` 五种状态的显示优先级。若未来重构把接线改错，12 个单测仍会全绿。
- 影响：回归保护只到纯函数边界；页面级行为当前靠静态核对与 T-003 补位。
- 建议：按计划由 `T-003` 的浏览器 E2E 覆盖；若后续引入 vitest/@vue/test-utils，可补组件级断言。本项不阻塞 T-002。

### [P3] 5xx 仍透传服务端原始 `err.message`

- 位置：`web/src/quiz-error.js:9`、`server/src/index.js:299`
- 问题：非 401、非网络失败的错误原样返回 `e.message`；服务端 5xx 会把 `err.message`（可能含 SQLite 内部信息）写给前端。
- 影响：可能向用户暴露内部错误文本；属改动前既有行为，T-002 未新增泄露面。
- 建议：如对内部信息敏感，可对 5xx 统一为通用文案；非阻塞，可另立任务。

### [P3] AC-001-2 的“上一次首题”语义需 Doc 固化

- 位置：`QuizView.vue:128`
- 问题：避重基线是“上一次成功抽题的 `queue[0]`”，不是“点击前屏幕上正在显示的题”。用户评分推进到后续题后点「重新抽题」，新首题可能恰好等于当前屏上那道题，虽然两次点击的“首题”不同。
- 影响：符合 AC-001-2 的字面（连续两次点击的首题不同），但可能与“不能感受到规律”的直觉有偏差；Dev 已在报告 §8 标注该假设。
- 建议：Doc 在 `05-decisions.md` 记录该语义（建议 D-005 一并记录“前端本地洗牌 + 上次首题避重”）；若用户要求避开“当前屏上题”，需另开任务，不属于本次返工。

### [P3] `04-tasks.md` 小规模文档不一致

- 回归：`web/e2e/crud.mjs:55-72` 的复习流程在静态上与改动兼容；server 42/42 全过。
- 工程面：无 `console.log`/`debugger`/`TODO`/`FIXME`；零新增依赖；构建不改动跟踪文件；`app/` 与部署配置未被触碰。
