## 3. 实现说明

`GET /api/quiz/due` 契约与调用方式不变（`web/src/api.js:64-69`、`QuizView.vue:124`），前端只对返回的 `items` 做二次排序：

1. 用 Fisher-Yates 在本地洗牌，避免依赖服务端顺序。这样即使线上仍跑旧版确定性排序，首题也不会恒定。
2. 若洗牌后的首题与「上一次成功抽题的首题」相同，且到期题 > 1，则从其余题中随机选一道换到首位。保证 `queue[0].uuid !== previousFirstUuid`（除「所有题 uuid 相同」这种异常数据）。
3. 到期题 = 1 时直接返回原队列，允许重复；到期题 = 0 时返回空数组，沿用现有空状态。
4. 失败时不更新 `previousFirstUuid`、不清空现有队列；`loading` 复位后按钮可再次点击重试。

没有采用「只把上次首题挪到第二位」的写法：判重依据是最终 `queue[0]`，任何下次抽题都会与本次实际首题比较；单测对此做了连续 20 次与 50 组种子的断言。
