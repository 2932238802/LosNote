## 3. P2-1 修复与证据

### 实现

- `web/src/request-guard.js:3-16`：每次 `start()` 调 `begin()` 取序号；响应落地前用 `isLatest()` 判断。
- `web/src/views/QuizView.vue:128-148`：
  - 成功分支：`if (!dueRequests.isLatest(request)) return;` 之后才写 `queue` 与 `previousFirstUuid`。
  - 失败分支：旧请求的 `catch` 直接返回，不覆盖 `error`。
  - `finally`：只有最新请求能复位 `loading`，旧请求先结束不会让新请求提前退出加载态。
- `web/src/views/QuizView.vue:4`：`loading` 期间禁用栏目下拉，配合按钮已有的 `:disabled="loading"`，从交互上避免再次发起取题。

### 自动化证据

`web/test/request-guard.test.js`：

| 用例 | 位置 | 断言 |
|---|---|---|
| 后发请求使先发请求失效 | `:15` | 第一次 `isLatest=true`，第二次 `begin()` 后第一次变 `false` |
| 乱序响应：旧响应后到也不会覆盖新队列 | `:24` | 新响应先落地、旧响应后落地，最终只应用 `["新栏目"]` |
| 旧请求先结束时不关闭最新请求的 loading | `:49` | 旧请求结束后 `loading` 仍为 `true`，新请求结束后才变 `false` |
| 旧请求失败不覆盖新请求的错误状态 | `:79` | 旧错误落地后 `error` 仍为空；新错误落地后才写入 |

测试结果：`cd web && npm test` → `tests 16 / pass 16 / fail 0`。

### 静态论证（组件接线）

- 旧响应即使晚到，也会在 `:134` / `:143` / `:147` 三处被 `isLatest` 拦住，不会写 `queue`、`previousFirstUuid` 或 `loading`。
- 下拉在 `:4` 被禁用，正常用户操作无法在请求在途时改变栏目；序号守卫仍覆盖极快双击等残余时序。

## 4. P2-2 修复与证据

### 实现

- `web/src/views/QuizView.vue:100-102`：`error` 只表示取题/评分错误；新增 `categoriesError` 只表示栏目加载失败。
- `web/src/views/QuizView.vue:117-126`：栏目成功时清空 `categoriesError`；失败时写入 `栏目加载失败：${quizErrorText(e)}`，401 与断网均得到友好文案。
- `web/src/views/QuizView.vue:17-18`：两者分两行显示，`error` 优先，避免同时失败时出现重复堆叠。
- `web/src/views/QuizView.vue:22-25`：「取题失败」空状态只判断 `!queue.length && error`，不再受 `categoriesError` 影响。

### 状态组合核对

| 场景 | 页面结果 |
|---|---|
| 栏目失败 + 取题成功且有题 | 显示栏目错误提示 + 题目面板 |
| 栏目失败 + 取题成功但 0 题 | 显示栏目错误提示 + 「这一轮没有到期的题」，**不会**显示「取题失败」 |
| 栏目失败 + 取题也失败 | 显示取题的友好错误 + 「取题失败」空状态；栏目错误不覆盖它 |
| 栏目成功 + 取题 401/断网 | 显示 `quizErrorText()` 的登录/网络提示；`loading` 复位后可重试 |

- `web/test/quiz-error.test.js:11-31`：401、`Failed to fetch`、`Load failed`、`NetworkError`、5xx 透传、空错误兜底均通过。
