## 4. 缺陷清单（按严重度）

### [P2] `.env` / 环境变量 `PORT` 与 compose 固定 8787 映射不一致，可能把成功更新误报为失败

- 位置：`update.sh:35`、`:257-260`；`docker-compose.yml:10`；`Dockerfile:14`
- 问题：脚本用 `PORT` 拼 `http://127.0.0.1:${PORT}` 做 health/指纹，但 compose 固定 `127.0.0.1:8787:8787`，容器内监听 8787；`PORT` 对实际部署无作用。
- 触发：`.env` 或 shell 设置 `PORT=9000`（`--help` 明确列为环境变量）。
- 影响：容器已成功重建，但 L5 访问错端口，30 秒后退出 1 并提示回滚；服务器 `.env` 若含 `PORT`，T-008 会直接失败。
- 证据：`.env` 加 `PORT=9999` 后输出 `× [L5 验证] GET http://127.0.0.1:9999/api/health ...`；compose 为 `${LOSNOTE_BIND:-127.0.0.1}:8787:8787`。
- 建议：删除 `PORT` 选项并从 `docker compose port losnote 8787` 取实际宿主端口；或让 compose 宿主端口由 `PORT` 驱动；L1 加 compose 端口预检。
- 置信度：高（机制）；中（生产 `.env` 是否含 `PORT` 未知）。

### [P2] 锁文件位于可预测的 `/tmp` 路径，`exec 9>` 跟随符号链接，存在本地文件截断 / 锁 DoS 风险

- 位置：`update.sh:86-97`
- 问题：`LOCK_FILE="${TMPDIR:-/tmp}/losnote-update-${LOCK_KEY}.lock"` 路径可预测；`exec 9>"$LOCK_FILE"` 会跟随符号链接并截断目标文件。
- 触发：多用户主机本地非特权用户预置符号链接；脚本以 root 运行。
- 影响：root 运行时可截断任意可写文件；非 root 运行时被持久化拒绝更新。单人 VPS 暴露面低。
- 建议：锁放到 `/run/lock` 或改用 `mkdir` 原子锁（不跟随符号链接），校验属主/权限。
- 置信度：高（机制）；低到中（环境可利用性）。

## 8. 残留风险

1. **真实 Docker 行为未验证（T-008）**：构建/重建、`compose run` 卷挂载、容器内 `VACUUM INTO`、备份权限、真实日志、第二次真实执行、真实 health/指纹。
2. **首次无镜像时 `compose run` 是否自动构建** `[待验证]`；若不自动构建，全新服务器首次执行会在 L2 以“备份失败”退出；建议 T-008 确认或给 `compose run` 加 `--build`。
3. **compose 项目名/卷名不一致**：新目录可能挂新空卷，服务看似“数据清空”；T-008 前用 `docker inspect losnote` 对比挂载卷、`docker compose config` 确认卷名。
4. **本地镜像 origin 过期**：脚本证明 HEAD == origin/main，不证明 origin/main 已同步 GitHub；若 `/opt/git/losnote.git` 旧，脚本仍报成功；CR-002 以 origin/main 为准，不算 AC 缺口。
5. **反向代理/CDN 缓存**：L5 只访问 127.0.0.1，不能证明 Caddy/Nginx/CDN 未缓存旧入口。
6. **`LOSNOTE_BIND` 为非回环 IP**：L5 可能误报失败。
7. **主机无 GNU date 且无 node**：L4 无法解析 StartedAt（目标 Ubuntu/Debian 可用）。
8. **health 30 秒上限**：大库/慢磁盘可能假失败。
9. **每次强制重启**：停机窗口需 T-008 记录。
10. **备份磁盘占用**：最多 14 份完整库，未压缩。
11. **update.sh 自更新**：拉取后只警告、继续旧逻辑，需要再执行一次。
12. **无自动化测试/shellcheck**：R-002 已接受，但后续修改风险较高。
