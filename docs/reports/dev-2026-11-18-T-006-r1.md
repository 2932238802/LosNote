## 2. P2 修复与证据

### P2-1 PORT 与实际端口不一致

- 修复：删除 `PORT` 环境变量与 `.env PORT` 读取；L3 之后执行 `docker compose port losnote 8787`，解析最后一段端口与宿主地址；`0.0.0.0` / `[::]` 使用 `127.0.0.1`，其他绑定地址按实际值使用；解析失败回退 8787 并 `warn`。
- 证据：伪仓库 `.env` 同时写 `PORT=9999`，shell 也设 `PORT=9999`，假 docker 返回 `0.0.0.0:18787`；脚本输出：
  - `健康检查：http://127.0.0.1:18787（端口来自 docker compose port losnote 8787）`
  - `health：{"ok":true,...}`
  - `✓ 更新完成`，退出 0
- 结论：`PORT=9999` 不再影响健康检查，实际使用 compose 映射端口。

### P2-2 锁文件安全

- 修复：移除 `/tmp` 可预测文件 + `exec 9>`；改为 `mkdir -m 700` 原子锁目录。优先 `/run/lock`（root 专属）；`/run/lock` 不存在或不可写时回退 `TMPDIR`，仍使用 `mkdir`，不跟随符号链接。锁内写 PID；`lock_is_stale` 用 `kill -0` 与 `ps -p` 判断；无 PID 且目录 mtime 超过 10 秒视为过期；过期时用 `mv` 原子移走旧目录再重建，避免两个进程同时清理；`trap cleanup_lock EXIT` 只清理自己持有的锁。
- 证据：
  - 活跃锁（PID 为当前 shell）：第二实例立即输出 `× [L1 代码] 已有另一个 update.sh 正在执行...`，退出 1；原锁目录保留。
  - 过期 PID（999999）：输出 `发现过期的更新锁（PID 999999），已清理并重试`，随后继续执行。
  - 无 PID 且目录 1 分钟前：输出 `发现过期的更新锁（PID 未知）`，清理并继续。
  - 无 PID 且目录新建：视为活跃，第二实例退出 1，原锁保留。
  - 成功执行后锁目录自动清理（`ls -d /run/lock/losnote-update-*.lock.d` 无残留）。

### P2-3 前置检查失败无阶段日志/回滚提示

- 修复：新增 `fail_precheck`，所有命令/环境前置失败统一输出：
  - `× [L1 代码] <原因>`
  - `  前置检查失败，未改动工作区，无需回滚。`
- 覆盖：缺 `.env`、缺 git、缺 docker、缺 compose v2、非 git 仓库、锁冲突。
- 证据：五类场景均退出 1，输出上述两行；没有改动工作区。脏工作区/非 main/detached HEAD 仍走 `fail_stage`，保留日志与回滚提示。

### P2-4 恢复提示缺 WAL/SHM 清理
